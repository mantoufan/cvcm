# cv.cm

Browser toolkit on a Cloudflare Worker with static assets (`wrangler deploy`; the old Pages project is only a rollback).

## Hard rules

1. Image and PDF tools (watermark, mosaic, collage, portrait-sim, convert, image-pdf, resize, crop, rotate, exif, meme, signature, favicon, screenshot, image-colors, tier-list, gif-maker, image-splitter, pdf-jpg, merge-pdf, compress-pdf, split-pdf, invoice) process files in the page. Do not add upload APIs for those tools, analytics beacons, or extra third-party `connect-src` hosts. Site analytics (GA4 `G-5X2J6QT5KK`, `src/shared/analytics.ts`) skips them, the audio tools (audio, audio-cutter, audio-joiner, mic-test, decibel-meter, voice-recorder), the guitar tuner, the webcam test, the screen recorder and clip notes: those pages get a CSP without the GA hosts and send no hits. Add new file tools to `UNTRACKED_TOOLS`.
2. Clipboard text lives in D1 (`cvcm` / binding `DB`, table `clips`). Non-text files go to s3.cv.cm bucket `files` via Worker-presigned PUT. No KV or R2.
3. The Worker serves static files, locale redirects, security headers, `/api/clip`, and `/api/clip/upload`. Reject other `POST` / `PUT` / `PATCH` / `DELETE` with 405.
4. Clipboard notes: no login; auto-delete after 10 views or 24 hours. Text max 64 KB, files max 32 MB. No listing endpoint.
5. New local tools process data with Web APIs in the page. Add a locale path, strings in `src/locales/*`, an entry in `src/shared/path.ts` `TOOLS`, and a lazy loader in `src/client/tools.ts` `TOOL_LOADERS` (never a static import in `main.ts`: each tool is its own chunk).
6. Tutorials must be minimal, complete, and illustrated (owner correction, 2026-09-13). Explain the whole task from preparation through completion with concise steps and meaningful instructional diagrams. Use captions to explain each image. Present tutorials, not exercise cards, assignments, submission requirements, or grading criteria. Keep photography first. JK/Lolita/Hanfu fashion examples use adults.
7. Design is plain pink and white, built for speed and search (owner, 2026-10-13): no decorative images, gradients, shadows or ornaments; lists are text links (`src/client/links.ts`). Covers appear only as `og:image`, never in the page. Tool-page how-tos are text (the live tool sits right above them); tutorial step diagrams and game walkthrough shots stay, lazy-loaded. Reference photos (`src/data/ref-photos.json`) are content: they are hotlinked from s1.mtf6.com (never copied to cv.cm or S3), credited and linked to their mfan8.com set, and shown only on reference pages. The one exception to "never copied": CC0 Shisei mannequin line art (`REF_MANNEQUINS` in `src/shared/ref.ts`, `public/covers/ref/`, served through `/covers/`, provenance in `docs/ref-mannequins.md`). Do not take images from ai-pose-gallery, ai-costume-gallery or repos mirroring them: their terms forbid reposting (owner, 2026-11-07).
8. Every sitemap page is prerendered at build (`scripts/prerender.mjs` runs the real client in happy-dom → `dist/_ssr/<path>/index.html`). The Worker puts that markup in `#app`, so the first paint needs no JS; the client then mounts the same page off-screen and swaps it in (`render()` in `main.ts`). Keep mounts deterministic and free of network calls at mount, or the page falls back to the Worker's text copy (the prerender logs skipped pages).
9. AI tools (`ai` group in `CATEGORIES`: `v`, `ai-image-generator`, `ai-music-generator`, `remove-background`, `image-upscaler`, `speech-to-text`, `depth-map`) run models in the page with Transformers.js + ONNX Runtime Web, in one module worker (`src/client/ai/worker.ts`), WebGPU first (fp16 when the adapter has `shader-f16`), threaded WASM otherwise. Never call an inference API, and the page never loads models from a third-party host: everything is served same-origin at `/ai/models/` and `/ai/ort/` by the Worker, which fetches catalog files only (`upstreamUrl` in `ai-models.ts`, pinned revisions, edge-cached a year; anything else is a real 404). Published models come straight from Hugging Face (or the model's `source`), the ONNX Runtime build from the npm CDN (jsDelivr), and only our own exports (`cvcm/*`, not on Hugging Face) are uploaded to s3.cv.cm `files/ai/` (`scripts/ai/mirror.mjs --upload`). No uploads for anything else (owner, 2026-11-03). Add models to `src/shared/ai-models.ts` with exact byte sizes. AI pages are cross-origin isolated (COEP `credentialless`; links into or out of them load a new document) and get a CSP with `'wasm-unsafe-eval'`; only `speech-to-text` (and the non-AI `mic-test`, `guitar-tuner`, `decibel-meter`, `voice-recorder` and `screen-recorder`, see `MIC_TOOLS` in path.ts) may use the microphone; links into a mic page load a new document. The camera is likewise allowed only on `webcam-test` (`CAMERA_TOOLS`), and screen capture only on `screen-recorder` (`SCREEN_TOOLS`, `display-capture`). Mounts must not download anything: models load on first file (small or cached ones may warm on hover). One exception to the runtime: `ai-music-generator` runs Magenta MusicVAE on TensorFlow.js 2 in its own module worker (`model-worker.ts`, with `worker-shim.ts` imported first to give Magenta a `window`); its weights come from Magenta's bucket through the Worker like the others (`trio` in `ai-models.ts`, `source`; the bucket has no versions, the checkpoint has been frozen since 2019), and the `seedrandomNoEval` Vite plugin (also in `worker.plugins`) removes seedrandom's `eval`, failing the build if any is left (the CSP has no `'unsafe-eval'`).
10. Tool covers for `og:image` (`public/covers/*-sweet.jpg`, 1280×720 JPEG): generate with **Codex** using existing covers as style references (same pink twin-tail chibi, lace bonnet, cream-pink room). When Codex has no quota, use GPT Image on kie.ai with the same prompt and references (owner, 2026-11-06). Do not use Grok `image_gen` for new tool covers. See `docs/tool-cover-prompts.md`.

## Deploy

CI (`.github/workflows/deploy.yml`) ships every push to main. The Cloudflare API token needs **Workers Scripts edit + Workers Routes edit (cv.cm) + D1 + DNS**. By hand:

```
npm run build
npx wrangler d1 migrations apply cvcm --remote
npx wrangler deploy
```

From a slow uplink the asset upload and the 25 MiB script upload can time out; let CI deploy instead.

`dist/_worker.js` is the Worker, already bundled by `scripts/build-worker.mjs` as UTF-8 (wrangler's own bundle escapes CJK copy as `\uXXXX`). cv.cm runs as a Worker with static assets, not Pages: `wrangler deploy` (CI does it) reads `wrangler.jsonc`, which sets `main` to that file with `no_bundle` and `find_additional_modules: false` (dist/ also holds the client chunks), and the build writes `dist/.assetsignore` so the script is not uploaded as an asset. Limits: the Worker may be 64 MiB uncompressed (wrangler's "Total Upload"), a single asset 25 MiB, and an asset directory 20,000 files on the free plan. Secrets `S3_ACCESS_KEY_ID` and `S3_SECRET_ACCESS_KEY` are set with `wrangler secret put`. The routes `cv.cm/*` and `www.cv.cm/*` in `wrangler.jsonc` send the domain to the Worker (`wrangler deploy` creates them); the DNS records still point at the old `cvcm` Pages project, kept only as a short-term rollback: delete the two routes (dashboard or API) to fall back to it at once, then revert the config. CI no longer deploys Pages, so that build ages; once a D1 migration it does not know has run, roll back by reverting and redeploying the Worker instead. Domain: `cv.cm`. D1 database id: `1a809cf5-bb42-4f8d-b2c6-6cd7430226c5`.
